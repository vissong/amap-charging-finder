# 高德充电站 H5 设计说明

## 1. 目标

创建一个适合手机竖屏与汽车车机横屏访问的 H5，帮助用户完成两项任务：

1. 按 3、5、10、20、50 公里范围查找当前位置附近的充电站。
2. 在识别到用户正在行进后，按行进方向推荐前方充电站；当较可信地识别到用户位于高速公路时，优先推荐前方服务区内或服务区附近的充电站。

项目只展示高德公开 Web Service API 实际返回的数据，不模拟品牌、充电枪数量、功率、价格或忙闲状态。用户可从站点详情跳转到高德地图 App 或高德 H5，继续查看充电详情和导航。

## 2. 产品边界

### 2.1 首版包含

- 浏览器精确定位与持续定位。
- 附近充电站查询、距离排序和范围切换。
- 行进状态、速度和行进方向计算。
- 前方候选筛选与推荐排序。
- 高速状态的启发式识别。
- 高速服务区查询及充电站关联。
- 站点真实字段详情。
- 高德地图 App/H5 跳转。
- 手机竖屏与车机横屏响应式界面。
- 定位、权限、网络和高德接口异常处理。

### 2.2 首版不包含

- 充电枪实时忙闲状态。
- 总枪数、快充枪数、慢充枪数。
- 充电功率、接口标准、电价和服务费。
- 启动充电、订单和支付能力。
- 导航 SDK 级别的道路匹配、轨迹纠偏和后台持续导航。
- 运营商或第三方充电聚合平台接入。

## 3. 数据来源与约束

### 3.1 高德地点搜索

服务端调用高德地点搜索 2.0 周边搜索：

```text
GET https://restapi.amap.com/v5/place/around
```

固定使用汽车充电站 POI 类型 `011100`，并请求：

```text
show_fields=business,navi,photos,children
```

单次查询半径不超过官方允许的 50,000 米，单页最多请求 25 条。站点卡片和详情只渲染响应中真实存在的字段，包括：

- `id`
- `parent`
- `name`
- `location`
- `distance`
- `type`
- `typecode`
- `pname`
- `cityname`
- `adname`
- `address`
- `business`
- `navi`
- `photos`
- `children`

字段为空、空数组或未返回时不渲染对应信息。高德返回的 `distance` 不作为列表距离依据；服务端使用请求中心点与 POI `location` 自行计算，并按查询半径二次过滤。页面统一提供“实时充电信息请前往高德地图查看”的说明，不使用占位数字冒充实时数据。

官方参考：

- <https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch>
- <https://lbs.amap.com/api/webservice/download>

### 3.2 逆地理编码

服务端按节流策略调用：

```text
GET https://restapi.amap.com/v3/geocode/regeo
```

使用 `extensions=all` 获取格式化地址与邻近道路。道路名称和道路距离只用于高速状态的启发式判断，不对外宣称为导航级道路匹配结果。

官方参考：

- <https://lbs.amap.com/api/webservice/guide/api/georegeo>

### 3.3 高速服务区

高速服务区使用高德 POI 类型 `180300`。当高速状态为“较可信”或“可能”时，在当前点周边按同一推荐半径查询服务区。

充电站与服务区按以下优先级关联：

1. 充电站 `parent` 与服务区 `id` 一致。
2. 充电站名称或地址包含服务区名称。
3. 两者空间距离不超过 1,200 米，且均处于当前行进方向的前方扇区。

第 1、2 种关联可显示“服务区内”；仅由第 3 种规则关联时显示“服务区附近”，避免把空间推断表述成确定事实。

### 3.4 高德跳转

详情操作通过高德 URI API 生成标点或导航链接，使用高德坐标系并设置 `callnative=1`。移动端尝试调起高德地图 App，未安装或不支持时由高德 URI 页面回退到 H5。

官方参考：

- <https://lbs.amap.com/api/uri-api/gettingstarted>

## 4. 系统架构

采用单仓库、单 Node 服务的结构：

```text
浏览器 H5
  ├─ 浏览器 Geolocation API
  ├─ 道路雷达与结果界面
  └─ /api 请求
       ↓
Node/Express 服务端
  ├─ 参数校验与频率保护
  ├─ 高德响应归一化
  └─ 高德 Web Service API
```

前端使用 React、TypeScript 和 Vite。服务端使用 Express，通过环境变量 `AMAP_WEB_SERVICE_KEY` 读取已经验证可用的 Web Service Key。生产构建后由同一 Node 服务提供静态 H5 和 `/api` 接口。

Web Service Key 不进入前端构建产物，不写入源码和 Git。仓库提供 `.env.example`，真实值只保存在被 `.gitignore` 忽略的 `.env`。

## 5. 前端信息架构

### 5.1 全局状态栏

展示以下实时状态：

- 定位状态：定位中、定位正常、精度较低、定位失败。
- 当前速度：有可信样本时显示 km/h，否则显示“等待速度”。
- 当前道路：逆地理编码有值时显示。
- 场景状态：静止、行进中、可能在高速、已识别高速。

状态栏不得用 IP 城市定位结果冒充精确行车定位。

### 5.2 主视图

主视图采用“道路雷达”而不是内嵌地图：

- 用户位置固定在雷达下方偏中位置。
- 雷达朝向随平滑后的行进方向旋转。
- 附近模式显示完整圆形范围。
- 前方模式突出左右各 60° 的前向扇区。
- 站点按相对距离落在雷达中，推荐优先级通过尺寸、编号和颜色表达。
- 服务区站点使用独立的道路服务区标识，不使用虚构品牌图标。

道路雷达仅表达相对方向和距离，不绘制虚构道路或宣称是真实地图。

### 5.3 模式与范围

一级模式只有两个：

- 附近充电
- 前方推荐

搜索范围为 3、5、10、20、50 公里，默认 10 公里。切换范围会触发重新查询。

附近模式按直线距离升序排列。前方模式在行进方向尚不可信时展示引导状态“行驶一段距离后自动推荐”，仍允许用户切回附近模式使用。

### 5.4 结果列表与详情

手机竖屏中，结果列表位于雷达下方；车机横屏中，雷达与结果列表左右分栏。卡片默认展示：

- 站点名称。
- 距离。
- 相对方向。
- 地址摘要。
- 营业状态描述，仅在高德返回营业时间时展示。
- “服务区内”或“服务区附近”标识。

点击卡片在原列表位置展开详情，不使用遮挡驾驶信息的居中弹窗。详情按真实返回值展示电话、营业时间、类型、别名、入口/出口、图片和子 POI。主要操作为“高德查看”，次要操作为收起详情。

## 6. 定位、行进与方向算法

### 6.1 定位采样

前端调用 `navigator.geolocation.watchPosition`，配置：

- `enableHighAccuracy: true`
- `maximumAge: 3000`
- `timeout: 10000`

生产环境必须使用 HTTPS；localhost 可用于本地开发。

每个有效样本包含时间、经纬度、精度、设备速度和设备方向。精度大于 100 米的样本可用于显示当前位置状态，但不用于更新行进方向和高速判断。

浏览器 Geolocation 坐标按 WGS84 处理。在常用 GCJ-02 有效矩形范围内，前端先转换为 GCJ-02，再用于高德周边查询、轨迹计算和前方判断。产品仅支持中国大陆充电站查询，不承担境外查询或精确国界识别。站点距离由服务端根据转换后的当前位置与高德 POI 坐标使用 Haversine 公式计算并取整到米，不采用高德响应中的 `distance`，也不表示道路导航里程。

### 6.2 速度

优先使用设备返回的非负 `coords.speed`。设备不返回速度时，用相邻有效点的 Haversine 距离除以时间差计算速度。

使用最近 3 个可信速度样本的中位数抑制漂移：

- 连续 2 次中位速度不低于 3 m/s（约 10.8 km/h）时进入“行进中”。
- 中位速度低于 1.5 m/s 且持续 15 秒时回到“静止”。

### 6.3 方向

设备在移动状态下返回有效 `coords.heading` 时优先使用。否则，当相邻有效点距离至少 10 米时，根据两点计算地理方位角。

最近 3 个可信方向样本通过圆形平均平滑。没有可信方向时不输出前方推荐。

### 6.4 查询刷新

首次获得精确位置后立即查询。此后满足任一条件时刷新：

- 距上次查询位置移动至少 500 米。
- 平滑方向变化至少 20°。
- 距上次查询至少 30 秒。
- 用户切换模式或搜索范围。

同时只保留一个有效请求；新请求发起时取消旧请求，避免过期响应覆盖新结果。

## 7. 推荐算法

### 7.1 前方筛选

计算当前位置到每个站点的方位角，并求它与当前行进方向的最小夹角。夹角不超过 60°的站点进入前方候选。

### 7.2 高速状态

高速状态分为三级：

- `normal`：没有高速证据。
- `possible`：邻近道路或格式化地址包含高速特征，但道路距离或定位精度不足。
- `confirmed`：最近道路名称包含“高速”“高速公路”或 “Expressway”，道路距离不超过 50 米，且当前定位精度不超过 50 米。

单纯速度较快不能确认高速，只能作为 `possible` 的辅助证据。道路名称规则集中配置并可测试，避免散落在界面代码中。

### 7.3 排序

普通行进场景按以下因素排序：

1. 与当前方向夹角更小。
2. 距离更近。

高速状态为 `possible` 或 `confirmed` 时，排序优先级调整为：

1. 已关联的前方服务区充电站。
2. 与当前方向夹角更小。
3. 距离更近。

列表最多突出显示 3 个推荐，其余前方候选仍可浏览。界面不展示未经高德路径规划验证的“预计到达时间”。

## 8. 视觉与响应式设计

视觉方向为深色、高对比、工业仪表盘风格：

- 背景使用带暖色倾向的深墨色，避免纯黑。
- 充电状态使用黄绿色，推荐序号使用高亮暖黄，警告使用琥珀色。
- 数字、距离和速度采用窄体仪表字体；中文正文采用清晰的中文无衬线字体。
- 通过道路标线、刻度、方向箭头和编号建立识别度，不使用霓虹渐变、玻璃拟态或通用卡片墙。
- 触控目标最小 48×48 CSS 像素。
- 所有状态不仅依赖颜色，同时使用文本、图形或编号表达。
- 尊重 `prefers-reduced-motion`，关闭非必要转场和雷达旋转动画。

响应式断点以可用布局为准：

- 窄屏：单列，状态栏、雷达、模式控件、列表顺序排列。
- 宽屏/车机：状态栏横向压缩，雷达约占 55%，列表约占 45%。
- 横屏低高度：缩小装饰刻度，保留状态、模式、范围、推荐和高德跳转等关键功能。

## 9. 错误与降级

- 未配置服务端 Key：服务启动失败并输出不含 Key 的明确配置提示。
- 定位权限未授权：说明如何开启权限，并提供重新定位按钮。
- 浏览器不支持定位：显示能力限制，不发起附近查询。
- 定位精度低：允许附近查询，但暂停方向和高速确认。
- 高德限流或服务错误：展示高德返回的可读错误分类，提供重试，不泄露 Key 或完整上游响应。
- 无查询结果：保留当前范围和模式，建议扩大搜索范围。
- 前方无结果：允许查看全部附近站点，不伪造推荐。
- App 调起失败：保留高德 URI H5 页面作为回退。

## 10. API 设计

### 10.1 查询站点

```text
GET /api/charging-stations?lng=<number>&lat=<number>&radius=<meters>
```

服务端限制：

- 经度 `73` 至 `136`。
- 纬度 `3` 至 `54`。
- 半径只接受 `3000、5000、10000、20000、50000`。

响应返回归一化的站点数组和查询元数据，不返回上游 Key。

### 10.2 查询道路场景

```text
GET /api/road-context?lng=<number>&lat=<number>
```

返回格式化地址、最近道路名称、道路距离及服务端计算的高速证据字段。最终高速状态仍由前端结合定位精度计算。

### 10.3 查询服务区

```text
GET /api/service-areas?lng=<number>&lat=<number>&radius=<meters>
```

仅在前端处于行进状态且高速状态不是 `normal` 时调用。

## 11. 测试策略

### 11.1 单元测试

使用 Vitest 覆盖：

- Haversine 距离。
- 两点方位角。
- 最小角度差与前方 60° 边界。
- 速度中位数和移动状态转换。
- 圆形方向平均的 0°/360°边界。
- 高速状态三级判断。
- 服务区三种关联规则。
- 普通场景和高速场景排序。
- 高德空数组/字符串混合字段归一化。
- 高德 URI 生成与参数编码。

### 11.2 服务端测试

使用固定的高德响应夹具测试参数校验、归一化、上游错误映射和 Key 不泄露。测试不依赖真实高德服务，避免消耗配额和产生不稳定结果。

### 11.3 端到端测试

使用 Playwright 注入定位与 API 响应，覆盖：

- 手机竖屏附近查询。
- 手机从静止切换到行进并出现前方推荐。
- 高速场景服务区优先。
- 车机横屏双栏布局。
- 权限拒绝、无结果和接口失败。
- 点击“高德查看”生成正确的 URI。

### 11.4 人工视觉验证

至少验证以下视口：

- 390×844：常见手机竖屏。
- 844×390：手机横屏。
- 1280×720：常见车机横屏。

检查内容溢出、触控尺寸、文字可读性、列表滚动和减少动态效果模式。

## 12. 完成标准

- 使用已验证的高德 Web Service Key 能查询真实充电站。
- Key 不存在于前端源码、构建产物、Git diff 或浏览器网络请求中。
- 附近模式支持 3 至 50 公里范围并正确排序。
- 有可信方向时能筛选前方 120°扇区内的候选。
- 高速状态下服务区关联站点优先，关联来源表述准确。
- 缺失的枪数、功率、价格和忙闲不以模拟值展示。
- 手机与车机视口均完成端到端和视觉验证。
- 测试、类型检查、构建和服务启动检查全部通过。
